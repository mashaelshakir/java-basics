مقدمة في البرمجة

Intro to Programming

1) مقدمة عن البرمجة | Intro to Programming Concepts

البرمجة (Programming) = عملية كتابة مجموعة من الأوامر (Instructions) بلغة يفهمها الحاسوب، لحل مشكلة معيّنة أو تنفيذ مهمة محددة.

مكونات البرنامج (Program Components)

  • البيانات (Data): المعلومات اللي البرنامج يتعامل معها (أرقام، نصوص...).
  • العمليات (Operations): الأفعال اللي تُطبّق على البيانات (جمع، طرح، مقارنة...).
  • التحكم بالتدفق (Control Flow): ترتيب تنفيذ الأوامر — بالتسلسل، أو بشرط، أو بتكرار.

كيف ينفّذ الحاسوب البرنامج؟

البرنامج يُنفَّذ بشكل تسلسلي (Sequential) — سطر بسطر من الأعلى للأسفل — إلا إذا وُجد أمر شرط (Condition) أو تكرار (Loop) يغيّر مسار التنفيذ.
هذي الدورة تشرح المفاهيم بشكل عام (Pseudocode/منطق) بدون التقيد بلغة معينة، عشان أي لغة برمجة (Java, Python, C++...) تطبّق نفس المفاهيم بأسلوب Syntax مختلف.

2) المتغيرات | Variables

المتغيّر (Variable) = مكان في الذاكرة (Memory) له اسم، يُخزَّن فيه قيمة يمكن تغييرها أثناء تنفيذ البرنامج.

مكونات المتغير

  • النوع (Type): يحدد نوع القيمة (رقم، نص، ...).
  • الاسم (Identifier): يُستخدم للإشارة للمتغير واسترجاع قيمته.
  • القيمة (Value): البيانات المخزّنة فعليًا.
// تعريف متغير واعطاءه قيمة
int age = 20;
int age;      // تعريف بدون قيمة (declaration)
age = 20;   // اسناد القيمة لاحقًا (assignment)
تمثيل المتغير في الذاكرة
age→
20
الاسم "age" يشير إلى خانة في الذاكرة تحتوي القيمة 20. لو غيّرنا age = 25، تتغيّر القيمة داخل نفس الخانة.

قواعد تسمية المتغيرات

  • يبدأ بحرف أو _ أو $ (مو برقم).
  • ما يحتوي مسافات أو رموز خاصة (مثل @ # -).
  • حساس لحالة الأحرف (Case-Sensitive): age ≠ Age.
  • ما يكون كلمة محجوزة (Reserved Word) مثل int, if.
المتغيرات تخلي البرنامج ديناميكي — بدل ما نكتب القيمة ثابتة بكل مكان نستخدمها، نخزنها مرة وحدة ونعيد استخدام الاسم، ولو تغيّرت القيمة يكفي نغيّرها بمكان واحد.

3) الثوابت | Constants

الثابت (Constant) = مكان بالذاكرة له اسم وقيمة، لكن لا يمكن تغيير قيمته بعد تعريفه. 
final double PI = 3.14159;
PI = 3.14;  // ❌ خطأ compile error — لا يمكن تعديل ثابت
Variable

Constant
القيمة ثابتة من لحظة التعريف ولا تتغيّر أبدًا.
نستخدم الثوابت للقيم اللي من المفروض ما تتغيّر أبدًا (مثل PI، أو الحد الأقصى لعدد المقاعد)، لحماية البرنامج من تعديل غير مقصود لهذي القيم، ولزيادة وضوح الكود (اسم PI أوضح من كتابة 3.14159 بكل مكان).

4) التعليقات | Comments

التعليق (Comment) = نص داخل الكود يكتبه المبرمج للتوضيح، ولا يُنفَّذ من قبل الحاسوب (يتجاهله الـCompiler/Interpreter). 
// تعليق سطر واحد

/* تعليق
   متعدد الأسطر */

وظائف التعليقات

  • توضيح الغرض من جزء معيّن من الكود.
  • تعطيل جزء من الكود مؤقتًا بدون حذفه (أثناء الاختبار).
  • توثيق البرنامج لأي مبرمج آخر يقرأه لاحقًا (أو أنت نفسك بعد فترة).
التعليقات لا تؤثر على أداء البرنامج ولا تُترجم إلى تعليمات تنفيذية — وظيفتها للبشر فقط.

5) أنواع البيانات | Data Types

نوع البيانات (Data Type) = يحدد نوع القيمة اللي يخزنها المتغير، وحجم الذاكرة اللي تُحجز لها، والعمليات المسموحة عليها.

لماذا نحدد النوع؟

تحديد النوع يخلي الحاسوب يعرف كم مساحة يحجز في الذاكرة وأي عمليات مسموحة — مثلاً لا يمكن جمع نص مع رقم منطقيًا بنفس طريقة جمع رقمين، فالنوع يمنع أخطاء منطقية من الأساس.

7) الشروط | Conditions

جملة الشرط (Conditional Statement) = تسمح للبرنامج بأخذ قرار وتنفيذ مسار معيّن من الكود بناءً على تحقق شرط (Boolean).

If

if (age >= 18) {
    // ينفّذ فقط لو الشرط صحيح
    print("بالغ");
}

If / Else

if (age >= 18) {
    print("بالغ");
} else {
    print("قاصر");
}

If / Else if / Else

if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";
} else if (score >= 70) {
    grade = "C";
} else {
    grade = "F";
}
الترتيب مهم جدًا في else if — البرنامج يفحص الشروط بالتسلسل ويتوقف عند أول شرط صحيح، فلازم نرتب الشروط من الأخص للأعم (أو حسب المنطق المطلوب) وإلا نطلع بنتيجة خاطئة.

Switch

يُستخدم بدل سلسلة طويلة من else if لما نقارن متغير واحد بعدة قيم محددة.
switch (day) {
    case 1:
        print("الأحد");
        break;
    case 2:
        print("الاثنين");
        break;
    default:
        print("يوم غير معروف");
}
⚠ لو نسينا break، التنفيذ يستمر (يسقط/falls through) للـcase اللي بعده حتى لو ما تحقق شرطه — من أشهر الأخطاء اللي تُختبر.

Nested Conditions (شروط متداخلة)

if (age >= 18) {
    if (hasID) {
        print("مسموح الدخول");
    } else {
        print("يحتاج هوية");
    }
}

8) التكرار | Loops

حلقة التكرار (Loop) = تسمح بتنفيذ مجموعة أوامر عدة مرات بدون إعادة كتابتها يدويًا، إلى أن يتحقق شرط توقف.

For Loop

يُستخدم عندما نعرف عدد مرات التكرار مسبقًا.
for (int i = 0; i < 5; i++) {
    print(i);
}
0 1 2 3 4
  • Initialization: int i = 0 — ينفّذ مرة وحدة بالبداية.
  • Condition: i < 5 — يُفحص قبل كل تكرار.
  • Update: i++ — ينفّذ بعد كل تكرار.

While Loop

يُستخدم عندما لا نعرف عدد التكرارات مسبقًا — يستمر طالما الشرط صحيح، ويُفحص الشرط قبل أول تنفيذ.
int i = 0;
while (i < 5) {
    print(i);
    i++;
}

Do-While Loop

مثل While، لكن الشرط يُفحص بعد التنفيذ — لذلك الجسم ينفّذ مرة واحدة على الأقل حتى لو الشرط خطأ من البداية.
int i = 10;
do {
    print(i); // ينفّذ مرة وحدة رغم أن الشرط خطأ من البداية
    i++;
} while (i < 5);

10) الدوال | Functions

الدالة (Function) = مجموعة أوامر مُجمّعة تحت اسم واحد، تنفّذ مهمة محددة، ويمكن استدعاؤها (Call) عدة مرات من أي مكان بالبرنامج بدل إعادة كتابة نفس الكود.

مكونات الدالة

  • الاسم (Name): يُستخدم لاستدعاء الدالة.
  • المدخلات / المعاملات (Parameters): قيم تُمرَّر للدالة لتعمل عليها (اختيارية).
  • الجسم (Body): الأوامر اللي تُنفَّذ.
  • المخرجات (Return Value): القيمة اللي ترجعها الدالة بعد التنفيذ (اختيارية).
// تعريف دالة تجمع رقمين وترجع الناتج
int add(int a, int b) {
    int result = a + b;
    return result;
}

// استدعاء الدالة
int sum = add(5, 3);
print(sum);

void greet() {

Parameters (المعاملات الشكلية) vs Arguments (القيم الفعلية)

Parameter
الاسم المُعرَّف داخل تعريف الدالة، مثل a و b بالمثال أعلاه.
Argument
القيمة الفعلية اللي تُمرَّر عند الاستدعاء، مثل 5 و 3.

لماذا نستخدم الدوال؟

  • تقليل تكرار الكود (DRY: Don't Repeat Yourself).
  • تسهيل القراءة والصيانة — كل دالة مسؤولة عن مهمة واحدة واضحة.
  • سهولة الاختبار — نقدر نختبر كل دالة لحالها.

11) المشروع النهائي | Final Project

مشروع ختامي يجمع كل المفاهيم اللي درسناها بالدورة: متغيرات، ثوابت، أنواع بيانات، عمليات، شروط، تكرار، مصفوفات، ودوال — بمثال متكامل: "نظام تقييم درجات الطلاب".

فكرة المشروع (Pseudocode)

  1. تعريف مصفوفة (Array) تخزن درجات مجموعة طلاب.
  2. دالة (Function) تحوّل الدرجة الرقمية إلى تقدير حرفي (A/B/C/F) باستخدام شروط.
  3. حلقة تكرار (Loop) تمر على كل الطلاب وتطبع تقديرهم.
  4. ثابت (Constant) يحدد "درجة النجاح الدنيا".
  5. متغير (Variable) يحسب المعدل العام لكل الدرجات.
// ثابت لدرجة النجاح
final int PASS_MARK = 60;

// مصفوفة درجات الطلاب
int[] scores = {95, 72, 58, 88, 40};

// دالة تحوّل الدرجة إلى تقدير حرفي
char getGrade(int score) {
    if (score >= 90) {
        return 'A';
    } else if (score >= 80) {
        return 'B';
    } else if (score >= PASS_MARK) {
        return 'C';
    } else {
        return 'F';
    }
}

// متغير لحساب المجموع ثم المعدل
int total = 0;

// المرور على كل الطلاب
for (int i = 0; i < scores.length; i++) {
    char grade = getGrade(scores[i]);
    print("الطالب " + (i + 1) + ": الدرجة " + scores[i] + " - التقدير " + grade);
    total = total + scores[i];
}

double average = (double) total / scores.length;
print("المعدل العام: " + average);
الطالب 1: الدرجة 95 - التقدير A الطالب 2: الدرجة 72 - التقدير C الطالب 3: الدرجة 58 - التقدير F الطالب 4: الدرجة 88 - التقدير B الطالب 5: الدرجة 40 - التقدير F المعدل العام: 70.6

1) مقدمة عن لغة Java

Java لغة برمجة كائنية التوجه (Object-Oriented)، تعمل بمبدأ "اكتب مرة، شغّل في أي مكان" (Write Once, Run Anywhere).

كيف تعمل Java؟

  1. نكتب الكود بملف .java.
  2. الـCompiler يترجم الكود إلى Bytecode (ملف .class) — لغة وسيطة مو مفهومة مباشرة لأي جهاز.
  3. الـJVM (Java Virtual Machine) المثبتة على أي نظام تشغيل تشغّل الـBytecode.

Syntax أساسي

public class Main {
    public static void main(String[] args) {
        // نقطة بداية تنفيذ أي برنامج Java
    }

  • main هي الدالة اللي يبدأ منها تنفيذ البرنامج دائمًا.
  • اسم الملف لازم يطابق اسم الـClass العام (Public Class) بالضبط، بحساسية حالة الأحرف: Main.java.

تصميم المشروع (Pseudocode)

  1. مصفوفة ثابتة الحجم تخزن أسماء الطلاب، ومصفوفة موازية تخزن درجاتهم.
  2. Method لإضافة طالب جديد (بالبحث عن أول خانة فاضية بالمصفوفة).
  3. Method للبحث عن طالب بالاسم وعرض درجته.
  4. Method لعرض كل الطلاب المسجّلين.
  5. Try/Catch حول أي عملية وصول لعنصر بالمصفوفة، لتفادي توقف البرنامج عند index خاطئ.
public class StudentManager {
    private String[] names;
    private int[] scores;
    private int count; // عدد الطلاب المسجّلين فعليًا

    public StudentManager(int capacity) {
        names = new String[capacity];
        scores = new int[capacity];
        count = 0;
    }

    // إضافة طالب جديد
    public void addStudent(String name, int score) {
        try {
            names[count] = name;
            scores[count] = score;
            count++;
            System.out.println("تمت إضافة: " + name);
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("القائمة ممتلئة، لا يمكن إضافة طالب جديد");
        }
    }

    // البحث عن طالب بالاسم
    public void searchStudent(String name) {
        for (int i = 0; i < count; i++) {
            if (names[i].equals(name)) {
                System.out.println(name + " - الدرجة: " + scores[i]);
                return;
            }
        }
        System.out.println("الطالب غير موجود");
    }

    // عرض كل الطلاب
    public void displayAll() {
        for (int i = 0; i < count; i++) {
            System.out.println((i + 1) + ") " + names[i] + " - " + scores[i]);
        }
    }
}

مقدمة في OOP

Intro to Object Oriented Programming

1) مفهوم OOP

البرمجة كائنية التوجه (OOP) = أسلوب برمجة يعتمد على تنظيم البرنامج حول الكائنات (Objects) بدل الأوامر والدوال المتفرقة (كما بالبرمجة الإجرائية Procedural Programming).

Procedural vs OOP

Procedural Programming
البرنامج مجموعة دوال تُنفَّذ بالتسلسل على بيانات منفصلة عنها.
Object-Oriented Programming
البرنامج مجموعة كائنات، كل كائن يحتوي بياناته الخاصة (Attributes) وسلوكه الخاص (Methods) معًا.
OOP تحاكي طريقة تفكيرنا بالعالم الحقيقي (أشياء لها خصائص وسلوكيات)، وتخلي الكود أكثر تنظيمًا، وقابل لإعادة الاستخدام، وأسهل صيانة عند تكبير المشروع.

2) مفهوم Class و Object

الصنف (Class) = القالب أو المخطط (Blueprint) الذي يحدد الخصائص (Attributes) والسلوكيات (Methods) اللي هيكون عليها الكائن.

الكائن (Object) = نسخة فعلية (Instance) تم إنشاؤها من الـClass، ولها قيم حقيقية للخصائص.

مثال توضيحي

Class "Car" هو القالب العام (كل سيارة لها لون، ماركة، سرعة...) — بينما "سيارتي الحمراء تويوتا" هي Object فعلي (نسخة حقيقية بقيم محددة).
Class = Car
Attributes: color, brand, speed
Methods: accelerate(), brake()
Object = myCar
color = "Red"
brand = "Toyota"
speed = 0

Attributes و Methods

  • Attributes (الخصائص): البيانات اللي يحملها الكائن (تُسمى أيضًا Fields أو Properties).
  • Methods (السلوكيات): الأفعال اللي يقدر الكائن يسويها (الدوال المرتبطة بالـClass).

إنشاء Object (Instantiation)

عملية إنشاء كائن من Class تُسمى Instantiation، ويُشار للكائن الناتج بأنه Instance من ذلك الـClass.
هذا الفصل بين "التصميم العام" (Class) و"النسخ الفعلية" (Objects) يسمح بإنشاء عدد غير محدود من الكائنات المتشابهة بالبنية لكن المختلفة بالقيم، من نفس القالب — بدون إعادة كتابة الكود لكل واحد.

3) مبادئ OOP الأربعة

تقوم البرمجة كائنية التوجه على 4 مبادئ أساسية:
المبدأالفكرة الأساسية بجملة واحدة
Inheritance (الوراثة)صنف يرث خصائص وسلوكيات صنف آخر
Abstraction (التجريد)إخفاء التفاصيل المعقدة وعرض الأساسيات فقط
Encapsulation (التغليف)حماية البيانات الداخلية من الوصول المباشر غير المصرح
Polymorphism (تعدد الأشكال)نفس الاستدعاء يتصرف بطرق مختلفة حسب الكائن
هذي المبادئ الأربعة تحل مشاكل حقيقية بالبرمجة الكبيرة: تكرار الكود (يحلها Inheritance)، التعقيد الزائد (يحلها Abstraction)، تعديل البيانات بشكل غير آمن (يحلها Encapsulation)، وصعوبة التعامل مع أنواع مختلفة بشكل موحد (يحلها Polymorphism).

4) مفهوم Inheritance (الوراثة)

الوراثة (Inheritance) = آلية تسمح لصنف جديد (Subclass / Child Class) أن يرث الخصائص والسلوكيات من صنف موجود (Superclass / Parent Class)، مع إمكانية إضافة أو تعديل خصائصه الخاصة.

لماذا نحتاج الوراثة؟

لتفادي تكرار نفس الكود بعدة أصناف متشابهة — لو عندنا Car و Truck و Motorcycle، وكلهم يشتركون بخصائص (brand, speed) وسلوكيات (accelerate)، نضع هذي المشتركات بصنف عام "Vehicle" وكل صنف فرعي يرثها بدل تكرارها.

تمثيل الوراثة بـUML Diagram

Vehicle (Parent / Superclass) ▲ ┌────────┼────────┐ Car Truck Motorcycle (Children / Subclasses)
بالـUML، السهم المفتوح (▲) يشير دائمًا من الصنف الفرعي إلى الصنف الأب — اتجاه السهم يعني "يرث من".

مثال على مفهوم الوراثة

صنف "Vehicle" يحتوي: brand, speed, accelerate().
صنف "Car" يرث كل هذا تلقائيًا، ويضيف خاصية خاصة به مثل numberOfDoors.

أنواع العلاقة IS-A

الوراثة تُستخدم فقط لما توجد علاقة منطقية "IS-A" (هو نوع من) — مثلاً "Car IS-A Vehicle" منطقية. لو العلاقة "HAS-A" (يحتوي على)، الأصح نستخدم Composition مو Inheritance (مثل Person HAS-A Date وليس Person IS-A Date).

5) مفهوم Abstraction (التجريد)

التجريد (Abstraction) = إخفاء تفاصيل التنفيذ الداخلية المعقدة، وعرض فقط الوظائف الأساسية اللي يحتاجها المستخدم للتعامل مع الكائن.

مثال من الحياة الواقعية

لما تسوق سيارة، تستخدم المقود والدواسات (الواجهة البسيطة) — بدون ما تحتاج تفهم كيف يعمل المحرك بالتفصيل (التعقيد مخفي عنك).

Abstract Class و Abstract Method

المصطلحالوصف
Abstract Classصنف لا يمكن إنشاء كائن (Object) منه مباشرة — يُستخدم فقط كقالب أساسي يُورَّث منه
Abstract Methodدالة معرَّفة بالاسم والتوقيع فقط بدون جسم (تنفيذ) — كل صنف فرعي يرث Abstract Class ملزم يوفر تنفيذها الخاص
نستخدم Abstraction لما نبي نضمن أن كل الأصناف الفرعية توفّر تنفيذ معيّن (إجباري)، لكن كل صنف يطبقه بطريقته الخاصة — مثلاً "Shape" فيها abstract method اسمها calculateArea()، وكل شكل (Circle, Square) يطبقها بمعادلة مختلفة.

خصائص Abstract Class

  • لا يمكن إنشاء Object منه مباشرة (new AbstractClass() خطأ).
  • يمكن أن يحتوي methods عادية (لها تنفيذ) بالإضافة لـabstract methods.
  • أي صنف يرث منه، لازم يطبّق (Override) كل الـabstract methods، وإلا يصبح هو نفسه abstract.

6) مفهوم Encapsulation (التغليف)

التغليف (Encapsulation) = تجميع البيانات (Attributes) والدوال (Methods) اللي تعمل عليها داخل وحدة واحدة (Class)، مع إخفاء البيانات الداخلية عن الوصول المباشر من خارج الصنف.

لماذا نحتاج Encapsulation؟

لحماية البيانات من التعديل غير المتحكم فيه من خارج الصنف — مثلاً لو خاصية "balance" (رصيد حساب) مكشوفة مباشرة، أي كود خارجي يقدر يغيّرها لأي قيمة (حتى سالبة!) بدون تحقق. Encapsulation يجبر التعديل يمر عبر دوال محكومة تتحقق من صحة القيمة أولًا.

تطبيق Encapsulation

  1. نجعل الخصائص (Attributes) private — غير مرئية من خارج الصنف مباشرة.
  2. نوفّر دوال Getters و Setters عامة (public) للوصول للقيمة أو تعديلها بشكل محكوم.

مفهوم دوال Get() و Set()

النوعالوظيفة
Getterيرجع (يقرأ) قيمة الخاصية الخاصة دون السماح بتعديلها مباشرة
Setterيعدّل قيمة الخاصية بعد التحقق من صحتها (Validation)
مثال منطقي: setter لخاصية "age" يتحقق أن القيمة الجديدة ليست سالبة قبل قبولها — لو حاولنا وصولنا مباشر للخاصية بدون setter، ما كان في مكان لهذا التحقق.

7) مفهوم Polymorphism (تعدد الأشكال)

تعدد الأشكال (Polymorphism) = قدرة نفس الاستدعاء (Method Call) على التصرف بطرق مختلفة حسب نوع الكائن الفعلي اللي يُستدعى عليه.

مثال توضيحي

كل من Cat و Dog يرث من Animal ولديه method باسم makeSound()، لكن كل واحد ينفذها بشكل مختلف — استدعاء animal.makeSound() على كائن Cat يعطي "Meow"، وعلى Dog يعطي "Woof"، بنفس اسم الاستدعاء بالضبط.

نوعان أساسيان من Polymorphism

Compile-time (Static) Polymorphism
يتحدد وقت الترجمة — يتحقق عبر Method Overloading (نفس الاسم، Parameters مختلفة).
Runtime (Dynamic) Polymorphism
يتحدد وقت التشغيل الفعلي — يتحقق عبر Method Overriding (صنف فرعي يعيد تعريف method موروثة من الأب).
Polymorphism تسمح لنا نتعامل مع مجموعة كائنات من أنواع مختلفة (لكن مرتبطة بالوراثة) بشكل موحّد — مثلاً مصفوفة من Animal تحتوي Cat وDog معًا، ونقدر نستدعي makeSound() على كل عنصر بنفس السطر من الكود، وكل كائن يتصرف حسب نوعه الحقيقي.

3) الجزء الثاني: صنف Garage (الإدارة)

صنف Garage مسؤول عن إدارة مجموعة المركبات: إضافة، تحديث، حذف، وعرض — وهو مثال تطبيقي على Encapsulation (يحمي قائمة المركبات الداخلية) وAbstraction (يوفر واجهة بسيطة للتعامل معها).
import java.util.ArrayList;

public class Garage {
    private ArrayList<Vehicle> vehicles;

    public Garage() {
        vehicles = new ArrayList<>();
    }

    public void addVehicle(Vehicle v) {
        vehicles.add(v);
        System.out.println("تمت الإضافة: " + v);
    }

    public void removeVehicle(String plateNumber) {
        vehicles.removeIf(v -> v.getPlateNumber().equals(plateNumber));
    }

    public void displayVehicles() {
        for (Vehicle v : vehicles) {
            System.out.println(v);
        }
    }

    public void displayVehicleDetails(String plateNumber) {
        for (Vehicle v : vehicles) {
            if (v.getPlateNumber().equals(plateNumber)) {
                System.out.println(v);
                return;
            }
        }
        System.out.println("المركبة غير موجودة");
    }
}
